# 工作日志协议（通用版 · 逐字拷贝 · 禁止改写）

> 本文件由 dev-flow skill 分发，任何项目拷贝后逐字生效；源自两份实战版（单文件版与多机多文件版）的通用化，多机/多写作者场景一律以本版为准。
> 目标：换电脑、换会话、换人、换模型，接手者读三样东西即可**无缝续做**——不用问"上次做到哪"、不用重新读代码猜进度。三样东西：本协议（怎么记）、`plan.md` 的任务 checkbox（做什么、**进度唯一真源**）、`worklog/` 目录（做过什么、决策与坑）。

**第 0 铁律（先于一切）：换电脑靠 git，不 push 等于没做。** 文档与代码都在 git 仓里。**收工必须 `git commit && git push`（相关代码 + worklog 条目 + plan.md 勾选）；未 push 的进度视为未发生。** 换电脑第一步永远是所有涉及的仓 `git pull` 到最新。

## 1. 分工

| 物 | 是什么 | 谁更新 | 更新时机 |
|---|---|---|---|
| `plan.md` checkbox | 任务清单（**进度唯一真源**） | 做任务的人/AI | 开工标 `[~]`、验收通过标 `[x]`、受阻标 `[!]` |
| `worklog/<写作者>.md` | 时间倒序工作条目（做了什么、怎么验证、遇到什么、下一步） | 同上 | 每次开工开条目、收工补结果 |
| 本协议 | 记录规则本身 | 流程维护者 | 规则变更时 |

**铁律：进度只认 checkbox，事实只认 worklog。口头/记忆/聊天里的"我以为做完了"一律不算数。**

## 2. 多文件 worklog（解决多机打架）

单文件 worklog 在多机/多会话并行时必然撞车：各自在文件顶部插条目 → git pull 永远 non-fast-forward → 天天解冲突。采用**按写作者分文件**：

```
docs/<领域>/v<N>/worklog/
├─ <平台>-<机器名>-<写作者>.md     # 如 win-desktop-abc123-kimi.md
└─ ...                              # 每台机器/每个人/每个 AI 各自一个文件
```

命名：`<平台>-<机器名>-<写作者>.md`（平台：win/mac/linux；机器名小写去空格；写作者：人名或 AI 名）。**新机器/新写作者第一次开工前，先建自己的文件**，文件头写机器与写作者信息。

规则：

1. **只写自己的文件**——任何写作者不得编辑他人的 worklog 文件（纠错在自己文件里写评论条目并引用对方条目 ID）。每个文件只被单一写作者追加 → git 层面几乎永不冲突，pull 永远 fast-forward。
2. **条目顺序**：自己文件内时间倒序（最新在顶部）。
3. **条目 ID 全局唯一**：`[<任务号>]-<写作者>-<YYYYMMDD-HHmm>`（无任务号的杂项用 `[misc]`；长期有效的交接信息用 `[handoff]`，见 §4）。跨文件引用一律用 ID，不用"见某某文件第 N 行"。
4. **不需要合并**：恢复与查阅靠 grep 全目录（§3）。想要单文件视图可跑拼接排序脚本（非必须，不产生新真源）。
5. **共享文件只有 plan.md 的 checkbox**——冲突面缩到最小。配套纪律：改 checkbox 前**先 pull**；双写顺序（§4）保证崩溃时只少勾不多勾；真撞了，以"先 push 者"为准，后 push 者 rebase 后重勾并在自己 worklog 记一笔。

## 3. 换环境恢复流程（接手第一件事）

```
0. 确认协议可达：git log -1 -- docs/<领域>/ 不为空（否则文档目录从未 push，见第 0 铁律）；
   所有涉及的仓 git pull 到最新
1. 读 plan.md：grep -nE '^- \[[~!]\]' 锚定进行中/受阻任务——这是当前战线
   （不要只看 worklog 顶部——长期任务条目可能沉在各文件的深处）
2. checkbox ↔ worklog 对账：对每个 [~]/[!] 任务，grep 全 worklog/ 目录找其条目（按任务号）；
   状态不一致（[x] 但条目写🔄，或反之）先裁决再动手，不盲信任一方
3. 有 [~]：读该任务最新条目，从"下一步"续做；无 [~]：按 plan.md 依赖顺序取下一个可开工任务
4. ★ 信任但核验（防幻影地基："条目说做完了但代码被 revert/没 push/在错的仓"）：
   对本任务依赖的最近若干 [x] 任务，按其条目"代码状态"的 仓名@分支+commit hash 核验：
   git -C <repo> merge-base --is-ancestor <hash> <branch>，再重跑条目"验证"字段的命令
5. 开工：plan.md 标 [~]，在自己的 worklog 文件顶部开新条目（模板见 §4）
```

对 AI 的额外要求：恢复后**先复述**"当前在 <任务号>，上次做到 X（已核验 commit <hash> 在分支上/验证命令通过），接下来做 Y"，与用户确认无偏差再动手。

## 4. 条目模板（开工时写到自己文件顶部）

```markdown
## [<任务号>]-<写作者>-<YYYYMMDD-HHmm> 任务简称 — YYYY-MM-DD HH:MM 开始
- **执行者**: <AI 会话 / 人名>（机器：<机器名>）
- **目标**: 本次要完成的具体范围（对应 plan.md 的验收标准）
- **上下文**: 依赖哪些已完成任务、关键前置事实
- **进展**: <时间/步骤> 做了什么、改了哪些文件（带仓名的相对路径）；关键节点记 <仓名>@<分支> <commit hash>
- **验证**: 怎么证明做对了——写成可重跑的命令（恢复流程 §3-4 会重跑它），而非叙述
- **决策与坑**: 取舍、坑、TODO（附文件:行号）
- **代码状态**: 每个涉及的仓一行——`已 push <仓>@<分支> <hash>` / `仅本地未 push（有丢失风险，勿依赖）`
- **状态**: 🔄进行中 / ✅完成 / ⛔受阻(原因+需要什么解阻)
- **下一步**: 若未完成，交接给下一个执行者的第一步
```

- 收工更新同一条目，不新开（同一任务一条滚动更新直到完成）。
- **双写顺序**：先在自己 worklog 写 ✅ 并记 commit hash，再去 plan.md 勾 `[x]`，然后一并 commit+push——崩溃时宁可"worklog 已 ✅ 但 checkbox 未勾"，不可反过来。
- 状态符号：worklog 用 🔄/✅/⛔；plan.md checkbox 用 `[ ]/[~]/[x]/[!]`，一一对应。
- 代他人补记：必须标注「代记+依据」（据 plan 勾选/测试文件/提交记录重建）。
- 可选类型 `[handoff]`：换机/换会话必读的长期有效信息（环境拓扑、发布命令、凭证位置——只写位置，凭证本体永不入库）；事实变化时新开一条同主题 `[handoff]` 并声明取代旧条。

## 5. 记录纪律（什么必须记）

**必须记**：

- 任何任务状态变化（开工/完成/受阻）。
- 任何影响他人的决策：改了协议字段、定了开放问题、发现设计与实现不符修文档、引入新依赖/新配置。
- 任何"下次会忘"的坑：环境配置、非显然构建步骤、绕过的临时方案（附清理条件）。
- 与设计文档的偏差：**发现设计不可行时修文档而非静默偏离**，并记"因 X 修改了 NN-*.md 的 Z"。
- **过渡态必须有死线**：任何 observe/双轨/降级/豁免类机制立项时，任务条必须写明**关闭条件与最迟评估日**，每月扫一次超期项（不设死线的过渡机制会默认沉淀为永久机制）。
- 多机/多会话协作时的交接：在自己条目里写清"谁在哪个文件继续"（引用对方条目 ID）。

**不必记**：常规读代码、无结论的探索、纯格式调整。

### push 门禁处置

- 收工 commit/push 被仓内门禁拦截：以**套件全绿**为通过证据，修到全绿再推，不留红。
- 确需绕行（门禁本身故障，或与本次改动明确无关且短期不可修）：记录绕行标志（如 `GATE_BYPASS=1`）及原因到 worklog 条目（绕了什么门禁、为什么、清理条件/回补死线）——绕行必须留痕，且同样受"过渡态必须有死线"约束。

## 6. 与设计文档的关系

- 需求/设计文档（NN-*.md）是**约定**，`plan.md` 是**施工序**（checkbox 真源），worklog 是**施工记录**。
- 实施中发现约定错误：改对应文档 → plan.md 受影响处同步调整 → worklog 记"因 X 修改了 NN-*.md 的 Z" → 一并 commit+push。三者永远一致。
- 每个 PX 阶段全部任务 `[x]` 后：在自己的 worklog 文件写一条**阶段小结**（实际交付、与计划的偏差、给下一段的注意事项；多写作者时由该段负责人写，其余人可引用），并勾选 plan.md 的 PX 主项。

## 7. 设计阶段的适用

正式任务分解完成前，本协议即生效：设计文档的每次实质修改、每次验证实验，都按 §4 模板记到写作者自己的 worklog 文件，任务号用 `[design]`/`[<主题>-V?]`。
